# rn-observatory Mobile Integration Guide

This guide is intended for app teams integrating `@gaozh1024/rn-observatory` into Expo / React Native projects.

## 1. Minimum setup

Install:

```bash
pnpm add @gaozh1024/rn-observatory
```

Recommended production storage:

```bash
npx expo install @react-native-async-storage/async-storage
```

Root integration:

```tsx
import AsyncStorage from '@react-native-async-storage/async-storage';
import { AppProvider } from '@gaozh1024/rn-kit';
import {
  AppObservatoryProvider,
  createAsyncStorageObservatoryStorage,
} from '@gaozh1024/rn-observatory';

export default function App() {
  return (
    <AppObservatoryProvider
      enabled={!__DEV__}
      appId="your-app-id"
      appVersion="1.0.0"
      buildNumber="1"
      endpoint="https://your-domain.com/api/app-observatory/events"
      ingestToken="your-ingest-token"
      storage={createAsyncStorageObservatoryStorage(AsyncStorage)}
      identity={{ autoInstallId: true }}
      consent={{
        crash: true,
        analytics: true,
        device: true,
      }}
    >
      {observatory => (
        <AppProvider enableErrorBoundary healthReporter={observatory}>
          {children}
        </AppProvider>
      )}
    </AppObservatoryProvider>
  );
}
```

## 2. Critical note about analytics

`rn-observatory` defaults:

- `crash: true`
- `analytics: false`
- `device: false`

So if the app wants behavior analytics data in the backend, it must explicitly set:

```tsx
consent={{
  crash: true,
  analytics: true,
  device: true,
}}
```

If `analytics` is not enabled, `trackScreen()` and `trackEvent()` are no-ops.

## 3. Automatic screen tracking

If the app uses React Navigation, prefer the automatic helper instead of writing `trackScreen()` in every page.

```ts
import { createNavigationObservatoryTracker } from '@gaozh1024/rn-observatory';

const tracker = createNavigationObservatoryTracker(observatory, {
  mapRouteName: route => route.name,
});
```

Integration rule:

- call `tracker.onReady(() => getCurrentRoute())` after navigation is ready
- call `tracker.onStateChange(() => getCurrentRoute())` on route changes

The helper will:

- emit the initial `screen_view`
- emit the next `screen_view` when the route name changes
- attach `screen`, `routeName`, and `fromScreen`

## 4. Manual event tracking

Use `trackEvent()` for business actions:

```ts
await observatory.trackEvent('button.click', {
  screen: 'Checkout',
  target: 'submit-order',
});
```

Recommended event names:

- `button.click`
- `form.submit`
- `login.success`
- `login.failed`
- `checkout.pay_tap`
- `checkout.success`

For the maintained event taxonomy and recommended analytics properties, see:

- `docs/event-taxonomy.md`
- `docs/analytics-schema.md`
- `docs/analytics-tracking-template.md`

## 5. Manual error reporting

Use `captureException()` for caught business failures:

```ts
try {
  await submitOrder();
} catch (error) {
  await observatory.captureException(error, {
    source: 'order.submit',
    tags: { scene: 'checkout' },
  });
}
```

## 6. Why analytics may be missing in the backend

Check these first:

1. `consent.analytics` is not set to `true`
2. the app never calls `trackScreen()` or does not use navigation auto tracking
3. the app never calls `trackEvent()`
4. wrong `endpoint`
5. wrong `ingestToken`
6. wrong `appId`

Important:

Crash reporting working does not mean analytics is enabled.

## 7. Web support

Supported:

- Expo Web
- React Native Web

Not recommended:

- plain React + Vite apps
- plain Next.js browser apps

The SDK depends on `react-native` runtime APIs, so it should be treated as a React Native ecosystem SDK rather than a generic browser SDK.

## 8. Release metadata

If the app has a release pipeline, provide release metadata together with `appVersion` and `buildNumber`.

```tsx
<AppObservatoryProvider
  appId="your-app-id"
  appVersion="1.2.3"
  buildNumber="45"
  release={{
    id: 'release_20260524_001',
    channel: 'production',
    commitSha: 'abc123def456',
  }}
  endpoint="https://your-domain.com/api/app-observatory/events"
  ingestToken="your-ingest-token"
>
  {children}
</AppObservatoryProvider>
```

Recommended fields:

- `release.id`: unique release identifier generated by CI
- `release.channel`: `development`, `staging`, `gray`, `production`
- `release.commitSha`: git commit for the build

This helps the backend:

- correlate issues to releases
- build release health views
- support the current source map / symbolication workflow

For the full release / source map flow, see:

- `docs/release-integration.md`
- `docs/github-actions-release-example.md`
- `docs/expo-eas-release-template.md`
- `docs/react-native-cli-release-template.md`

## 9. Device information

The analytics pages in `app-observatory` become much more useful when events also include:

- `platform`
- `appVersion`
- `buildNumber`
- `device.model`
- `device.brand`

The core SDK only fills `platform` and `osVersion` by default. For official device recipes, see:

- `docs/device-info-recipes.md`

## 10. Native crash adapters
